# ADR 0013 新闻编辑部：收集、整理与早安卡精选

早安卡由调度器收集材料：今天的约定、新记下的记忆、夜思的结论、新写的笔记、追踪项的新条目、System health 和手机通知，模型逐段写成。owner 平时主要是丢文章链接让 agent 读、再追问看法，这些段落多数日子是空的；2026-10-22 的早安卡只有一句"夜思核对过了，没有新事项"。

同一天 owner 发来一张"60 秒读懂世界"的资讯海报：国内要闻 2 条、国际与财经 4 条、AI 与科技前沿 4 条，每条一个标题加一句话，末尾是今日关注 3 件。owner 要早安卡加上这种内容，二十分钟里换了四轮新闻源，最后选定 AI225 日报，加上中新网、BBC 中文和 FT 中文网。

追踪项为"有新的就报"设计，适合版本发布、价格变化、博客新文这类量小、每条都要报的东西。新闻要的是从大量条目里挑出几条。照追踪项处理有三个问题：

- 早安卡每次最多取 100 条待报条目，按追踪项 id 排序。中新网滚动新闻一天约 440 条，会占满名额，后面的源一直排不上。
- 没取到的条目留到下一次，越积越旧。
- AI225 的订阅源一天只有一个条目，摘要是本期概览，当期的二三十条要打开页面才看得到。

外面的做法各有侧重。AI225 日报由编辑挑选，每条带分类、★ 重要度和来源，多家报道同一件事的已经合并。AI Hot Radar 按真实性、相关性、重要性、来源权威度和内容质量给资讯打分，日报分国内、国际、模型、产品、社区、论文几个板块，并给 agent 开放 JSON 接口。TrendRadar 聚合各平台热榜，按排名、跨平台出现频次和热度加权排序，用一份按优先级写的自然语言兴趣清单让模型筛选，每组限条数；推送只发新条目，分析看全天。RSSHub 为没有订阅源的站点生成订阅源，规则由社区维护。RSS+ 脚本在任意页面上找订阅源：读 `<link rel="alternate">`，试探常见路径，匹配形似订阅源的链接，逐个验证。

Acorn 把这件事分成三层：收集交给订阅源、RSSHub 和 agent 自写的抓取脚本；整理和挑选由 Acorn 的模型按 owner 的偏好来做；结果进早安卡，也能随时查询。

## 决策

### 板块

板块是早安卡新闻部分的分组，有名称、顺序和偏好。偏好是按优先级排列的几行自然语言，例如"AI 与科技前沿：1. 模型与 agent；2. 开发工具；3. 融资少报"。owner 在对话里让 agent 增删板块、调整顺序和偏好，agent 用工具改。

### 新闻源与条目库

新闻源是 `news` 模式的追踪项，挂在一个板块下，沿用追踪项的抓取、基线、去重、出错退避和 URL policy。来源可以是 RSS 或 Atom、`rsshub:` 路由，或 agent 写的抓取脚本（S3）。

一个条目就是一期的源标为期刊源，例如 AI225 和 AI Hot Radar 的日报，内容要打开条目页面才看得到。

新闻源的状态有在用、试用、暂停和出错。试用源照常抓取和统计，不进早安卡。

新闻条目与追踪条目同表，保留 14 天。条目只存标题、摘要、链接和时间，不存全文。新闻条目是外部数据：不登记为记忆来源，不会成为关于 owner 的事实，正文里的指令不执行。

### 早安卡精选

新闻源按各自的间隔抓取；早安卡生成前，在用的新闻源全部再刷新一次。

模型拿到的候选按板块排列：板块的偏好；每个源上次早安卡以来的条目，按时间取最新的至多 30 条；期刊源最新一期还没用过的页面正文，按长度上限截断；以及上一份早安卡的新闻部分。这些候选用过即标为已报，没挑中的也不留到第二天。

模型按五个标准挑选：重要性、来源权威度、真实性、与板块偏好的相关性、相对上一份早安卡是否有新进展。输出先是各板块的编号条目，每条一个粗体标题、一句话和原文链接，共约 10 条，按重要性分到各板块；然后是今日关注 3 件；再接原有的个人部分（今天、记下的事、接下来、追踪、手机通知、需要你处理），有内容才出现。推送正文是今日关注的 3 件，有 System health 问题时占其中一行。

有了新闻源，早安卡每天都有材料。普通追踪项的 100 个名额按追踪项轮流分配，超出的写明"另有 N 条"，留到下一次。

### 后台编辑部

后台任务成批读入新条目的标题和摘要，按板块偏好打 1 到 5 分，并归入事件：新事件，或近几天已有的事件。期刊在入库时拆成单条。

事件把不同源报道的同一件事合在一起，记下首次出现、最近进展和所含条目，跨天跟踪。任务用租约 token，同一批重复处理结果一致；受 `news.daily_tokens` 约束，预算用完时剩下的条目留到下一个本地日。

早安卡从打过分的事件里挑，带上事件的进展。agent 有一个查询工具，按板块、时间和关键词查最近的事件，owner 随时可以问"最近 AI 圈有什么"。

### 扩展

`feed_discover` 给一个网址找订阅源：读页面的 `<link rel="alternate">`，试探 `/feed`、`/rss.xml`、`/atom.xml` 等常见路径，匹配页面里形似订阅源的链接，逐个抓取验证，返回每个源的标题、近来每天大约多少条和最近一条的时间。订阅源解析支持 JSON Feed。

owner 的服务器上跑一个 RSSHub。URL policy 只放行配置里的这个 RSSHub 地址，其余本机与内网地址照旧拒绝。

agent 可以为没有订阅源的站点写抓取脚本：技能包触发器（ADR 0010）的输出增加 `{"item": {...}}` 行，带 key、标题、链接、摘要和时间，写入绑定的新闻源。

agent 可以自己发现新源并加为试用源。夜思每周看一次试用源和在用源的统计：每天多少条、被挑中多少、与其他源的事件重合多少，据此提出转正或停用，写进早安卡或对话。owner 同意后才生效，在用源的停用同样如此。

### 边界变化

`/v1` 合同增加：追踪项的 `news` 模式、所属板块、期刊标记和试用状态；今天页的追踪列表标出板块。`web_fetch` 读 RSS、Atom 和其他 XML，订阅源返回条目列表。

本决定扩展 ADR 0003 的信息追踪：追踪项分成逐条报告的追踪和供挑选的新闻，早安卡由材料汇总变为新闻精选加个人部分。本决定扩展 ADR 0010 的触发器输出：除事件行和 `view_data` 行外，还接受 `item` 行。S2 增加配置 `news.daily_tokens`。

## 分期

| 期 | 内容 | 验收 |
|---|---|---|
| S1 | 板块；`news` 模式与期刊源；早安卡生成前刷新；候选与精选；早安卡技能；普通追踪的名额轮流分配；`web_fetch` 读订阅源 | 在测试机上按 owner 现有的四个源配好三个板块：早安卡给出约 10 条分到三个板块的新闻和今日关注 3 件，AI 板块的条目出自 AI225 当期日报，推送正文是今日关注；中新网没有占满候选；前一天报过且没有新进展的事不再出现；每个普通追踪项都有条目进入早安卡 |
| S2 | 条目保留与清理；后台打分与事件；`news.daily_tokens`；早安卡改读事件；查询工具 | BBC 中文和 FT 中文网报道同一件事时合成一个事件；问"最近 AI 圈有什么"时 agent 从条目库作答并附链接；预算用完的那天，剩下的条目在次日处理 |
| S3 | `feed_discover` 与 JSON Feed；RSSHub 与放行；触发器 `item` 行；试用与转正 | 给 agent 一个页面上没有标明订阅源的博客首页，它找到并验证订阅源；在 RSSHub 上加一条热榜路由并收到条目；agent 写的抓取脚本为一个没有订阅源的页面产出条目；一个试用源跑满一周后，夜思带着统计提出转正，owner 同意后它进入早安卡 |

## 代价

- 早安卡的输入从几百字变成上万字；S2 每天几百条条目的打分和归并，按标题和摘要成批处理也要几万 token。
- 精选的质量取决于源。按时间排的滚动新闻挑不出重要的，要选有人排过序的源，例如要闻、头条和日报；一个源好不好，要一周以上的统计才看得出来。
- 期刊源依赖上游的页面结构，改版后拆不出条目，需要 agent 调整。
- 抓取量变大，要遵守各站的频率限制和条款；部分站点要求注明出处，早安卡每条都附原文链接。
- RSSHub 是又一个要维护的服务；agent 写的抓取脚本会随站点改版失效，表现为新闻源出错。
- 多数日报在早上 8 点以后出刊，`briefing.at` 要设在上游出刊之后，否则用的是前一天那期。
