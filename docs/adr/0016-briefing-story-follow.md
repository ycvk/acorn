# ADR 0016 从早安卡的事件进入对话与跟进

测试机上 2026-10-10 到 10-29 的 51 个 run 里，owner 发起的有 35 个，多数是试功能和配新闻源，10-23 之后没有再发起对话；每天照常运行的只有早安卡和夜思。记忆从对话里来，长期记忆里只有 11 条 fact。关切只在 owner 交代多天的事时产生，游思 20 个时段都没有到期的关切。

owner 每天看的是此刻页的简报卡片，10-29 早上还批准了夜思提出的两个新闻源转正。卡片上的事件点一下只打开 Briefings 对话，长按只能标多报或少报；想多了解一件事，或想知道它后来怎样，都要自己起对话去问。

## 决策

### 点开一件事

简报卡片上的事件点一下进入这件事的对话。这件事还没有对话时，后端新建一个以事件标题为标题的对话，写一条 owner 消息「展开讲讲：<标题>」并起 run，App 打开这个对话看回复；已有对话时 App 直接打开它。

模型在这条消息旁看到它来自早安卡上的事件，以及事件的板块、标题、摘要、最新进展和最新至多 10 条条目的来源、时间、标题与链接，这些都标为外部数据。事件与条目 14 天后清理，这份内容在发消息时存下，对话里一直可读。回复讲清这件事是什么、为什么值得看，需要时读原文，链接列在回复里。

### 持续跟进

长按事件弹出的菜单在「多报这类」「少报这类」之上加「持续跟进」。选它时，后端在这件事的对话里（没有就新建）写一条 owner 消息「持续跟进：<标题>」并起 run，模型看到的事件内容与点开时相同，App 打开这个对话看回复。agent 以这条消息为来源建一个没有 outcome 的关切，标题写跟进的是什么，复查时间设在第二天；回复说明目前的进展和打算怎么跟。关切照常列在此刻页的「正在跟进」里。

正在跟进的事件在卡片上标「跟进中」，菜单里的「持续跟进」显示为已选，不能再选。不想再跟时，owner 在对话里说一声，agent 把关切标为放下；删除对话同样结束跟进。

### 游思检查跟进的事件

游思选中的关切建在跟进事件的对话里时，输入说明这是 owner 要求跟进的新闻事件，并附上跟进时存下的事件内容。新条目只会并入三天内更新过的事件，沉寂过的事再有进展会成为新的事件，所以 agent 用 `news_search` 和 `web_search` 找上次复查之后的进展，不只看原事件。

有新进展时，回复列出新进展和链接，并调用一次 `notify_owner`，标题是事件标题，正文是一句进展。没有时，回复一句没有新进展，不推送。每次结束都用 `concern` 写下这次查到什么，复查时间设到第二天。

### 接口与存储

SQLite 增加 `news_story_messages`：owner 消息、所在对话、事件、点开或跟进、发消息时存下的事件内容。删除对话一并删除它的这些记录；事件清理时这些记录保留。

`POST /v1/news/stories/{story_id}:discuss` 与 `POST /v1/news/stories/{story_id}:follow` 把消息写进这件事的对话（没有就新建）并起 run，返回对话 id、run 与消息的文字。事件已清理时返回 404；这件事的对话里有 run 在运行或等待审批时返回 409。`NowBriefingStory` 增加 `thread_id`（这件事有对话时）与 `following`（那个对话里有进行中或等待中的关切）。

### 边界变化

`/v1` 合同增加两个端点和 `NowBriefingStory` 的两个字段。游思对跟进事件的关切多一段输入，游思技能加跟进事件的做法。点简报卡片上的事件改为进入这件事的对话；点卡片的其他地方照旧打开 Briefings。

## 分期

| 期 | 内容 | 验收 |
|---|---|---|
| T1 | `news_story_messages` 与两个端点；消息旁的事件内容；游思的输入与技能；`NowBriefingStory` 的两个字段 | 测试机上经接口点开当天早安卡的一件事：新对话以事件标题为名，回复讲清这件事并附链接；再点开同一件事，消息写进同一个对话。跟进另一件：此刻页「正在跟进」出现它的关切，复查时间在第二天；之后的游思时段选中它，没有进展时回复一句、不推送，有进展时列出新链接并推送一次。删除这个对话后，关切从此刻页消失，`following` 变回 false |
| T2 | App 上点事件进入它的对话；长按菜单的「持续跟进」与「跟进中」标记 | owner 在手机上点一件事，打开新对话并看到回复流出来；返回再点，打开同一个对话；长按另一件选「持续跟进」，打开这件事的对话看到回复，返回后卡片上出现「跟进中」，「正在跟进」里多出这件事，再长按时「持续跟进」显示为已选 |

## 代价

- 游思每个时段只推进一件关切。跟进的事件一多，每件就不能每天查一次；owner 可以在设置里加游思时段，每多一个时段每天多一次模型调用。
- 关切由 agent 建。它没建或建得不对时，卡片上不出现「跟进中」，owner 要回对话里看。
- 没有新进展的检查也在对话里留一句话，跟进久了对话会变长。
- 每点开一件新事件就起一个 run，用的是 owner 对话的模型额度。
- 点事件不再打开 Briefings 对话，读早安卡全文要点卡片的标题区或「阅读全文」。
