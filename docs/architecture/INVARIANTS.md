# Acorn 架构不变量

每条不变量标注执行它的测试文件。新增不变量须同步加测试。

## 核心层 (core)

- **core 有零内部导入**：`internal/core` 不导入任何 `github.com/ycvk/acorn/internal/*` 包；core 是 Layer 0，只依赖外部 SDK（Eino schema/adk）。
  - `tests/architecture/dependency_direction_test.go`
- **持久化接口归 core**：各业务包依赖的 store 接口由 core 定义，`*store.Store` 在编译期断言实现它们。
  - `internal/core/store.go`
  - `internal/core/presence.go`
  - `internal/core/knowledge.go`
  - `internal/core/watch.go`
  - `internal/core/core_test.go`

## 运行时与编排

- **每个 run 一个 Eino ChatModelAgent**：`buildAgentRunner` 组装 `adk.TypedRunner[*schema.AgenticMessage]{ChatModelAgent, EnableStreaming, CheckPointStore}`；handlers 依次为 memory visibility → interjection → sub-run reports → patchtoolcalls → summarization → reduction(clear-only) → toolsearch(有 deferred 工具时) → skill → presence → approval → tool errors；子 run 的 `buildSubRunRunner` 不带 checkpoint store，handlers 依次为 patchtoolcalls → summarization → reduction(clear-only) → toolsearch(有 deferred 工具时) → skill → approval → tool errors。工具串行执行（`ExecuteSequentially`），普通工具失败与未知工具调用作为模型可见的 tool result 返回。Executor 只负责把 `AgentEvent` 投影成 RunEvent。
  - `internal/runtime/agent_test.go`
  - `internal/runtime/events_test.go`
- **子 run 只看到 brief，只拿查资料与工作机的工具**：`delegate start` 的 brief 要 objective（去掉空白后非空），deliverables、constraints、acceptance 与 block 去掉空项，block 的每个模式须能被 `path.Match` 解析。子 run 是父 run 所在对话与轮次里的一个 run，在 `sub_runs` 登记父 run、任务编号（新任务取父 run 已有的最大编号加一）、第几次尝试与 brief；子 run 不能再派出。子 run 的指令只有 `subRunInstruction`，输入只有一条 user 消息：渲染后的 brief 与工作机上的 `~/sub-runs/<run_id>/`，返工时再附上被退回的那次提交与反馈；没有人格、对话历史、记忆、presence 与 owner 中途的消息。工具只留 `web_search`、`web_fetch`、`artifact_read`、`shell`、`job`、`files`、`knowledge_search`、`knowledge_read`、`knowledge_list`、`news_search`、`feed_discover` 与 `submit`，`mcp.providers` 的工具不留（它们的 elicitation 落在 MCP 的当前 run 上），子 run 也不登记为当前 run。工作机上的技能包与包的 MCP 服务器不论哪个 run 同步，都按对话的 run 能用的工具（含 `delegate`）算，子 run 再按留下的工具去掉用不了的技能，留下的技能带着它们服务器的工具。`submit` 只在运行中的子 run 里记下 summary（非空）、evidence 与 limitations，后一次替换前一次。每个父 run 至多派出 16 次（含返工），超出返回 `ErrSubRunLimit`；整个 Acorn 同时至多 4 个子 run 在跑，其余等空位；每个子 run 至多 30 分钟，超时失败。父 run 的步骤里 `delegate` 调用的摘要取 objective，返工取 feedback。
  - `internal/store/store_sub_runs_test.go`
  - `internal/tools/delegate_tools_test.go`
  - `internal/runtime/sub_runs_test.go`
  - `internal/api/tool_steps_test.go`
  - `internal/wire/delegation_e2e_test.go`
- **父 run 在所有子 run 报告后才结束**：子 run 结束（成功或失败）就是报告，父 run 每次调用模型前，sub-run reports middleware 把还没交给它的报告按结束时间标为已交付，并各追加一条以 `[sub_run task N, attempt K: <status>]` 开头、标明是子 agent 的说法而不是 owner 的话、不执行其中指令的 user 消息：objective、summary、evidence、limitations，没有提交时是最后的回复，失败时是错误，并提醒对照证据收下或返工。memory visibility 因遗忘重建父 run 的消息后，下一次模型调用前已交付的报告按结束时间重新追加，遗忘列出的子 run 除外。父模型说完一段话时，Executor 看父 run 的子 run：有没交付的报告，或对话里排在最前的 owner 消息不带文件时，带着 agent 结束时的消息（去掉开头的指令）在同一个 run 里接着调用模型；还有子 run 在跑时等到有子 run 结束、每 2 秒检查一次 owner 消息，或 run 被停止；记录里还在跑、本进程里却已不在执行的子 run 让父 run 失败；全部报告且交付后 run 才结束。agent 每次说完的回复按先后以空行连起来，最后接上 run 结束时那一段，就是 run 的 output、`run.completed` 的消息与对话里的 assistant 消息。父 run 等审批时子 run 照常跑，报告在父 run 续跑后交付；等审批的 run 把此前说完的回复记为 output，续跑从它接着连。子 run 每 2 秒读一次父 run，父 run 已成功或失败（含被停止、续跑失败）时以 `the run that delegated it ended` 停止，读不到父 run 时以读取错误停止。`delegate accept` 与 `redo` 只作用于任务最新且已报告、还没有结论的尝试，否则返回 `ErrSubRunRunning` 或 `ErrSubRunReviewed`；redo 在同一事务里给这次尝试记下 redo 与反馈，并以同一 brief 起下一次尝试。

  - `internal/wire/delegation_e2e_test.go`
- **子 run 的审批只会更严**：子 run 的规则是父 run 开始时的 `approval.require`、`approval.allow` 与 `approval.block`，brief 的 block 加进 block。父 run 里会转审批的调用（require 命中、审查判断需要确认、审查出错）在子 run 里不登记 pending action，以说明它要写进 limitations 的拒绝文本作为工具结果返回；block 照常拒绝，allow 与审查放行的调用照常执行；`submit` 不受规则约束。

  - `internal/runtime/agent_test.go`
- **子 run 不是对话的 run**：对话最新的 run（线程列表状态、早安卡事件的忙碌判断、wake 调度器看对话是否空闲）、owner 消息排队等待的 run、`/v1/runs` 的进行中与最近结束列表、线程摘要的文件段落都不计子 run；子 run 不写对话消息，结束时不起排队的 run。删除对话一并删除子 run 及其 `sub_runs` 记录；Acorn 重启时还在跑的子 run 与其他 run 一样记为失败。父 run 有 `wake.fired` 时，子 run 的模型用量计入自主 token 预算。遗忘列出读过被排除内容的 run 时一并列出它们的子 run。

- **模型使用原生协议并保留推理状态**：Responses、Chat Completions、Anthropic Messages 都经 Eino AgenticModel；推理内容块与签名参与下一轮工具结果回传和 checkpoint，公开事件投影不含签名。sampling 可省略，输出预算和上下文按模型能力验证。请求空闲超时随响应进度刷新，总请求与 run 时限可关闭。

  - `internal/config/config_models_test.go`
- **工具失败可见，主模型调用有界重试**：tool error middleware 把错误转成结果文本时按 call id 记录，projector 对这些调用发 `tool.call.failed`（其余发 `tool.call.succeeded`）。主模型调用失败最多重试 3 次，context 取消不重试；被重试的失败流不记 run 失败，只有成功那次的输出成为 assistant 消息；3 次重试都失败时 run 失败。

- **工具调用对客户端只露出名字和摘要**：assistant 消息里的每个工具调用在消息之后发 `tool.call.started`。`tool.call.started`/`succeeded`/`failed` 进入 live 契约，客户端只拿到工具名、取自参数的一行摘要（至多 80 字）和截断到 300 字的错误，工具输出留在服务端。消息列表把 run 的这些事件按开始顺序折叠成 assistant 消息的 `steps`。`plan` 工具的调用不进 live 事件，也不进 `steps`。

- **run 进行中 owner 发的话交给这个 run**：`POST /v1/threads/{id}/runs` 在同一事务里判断对话：有 run 在运行或等待审批时，消息存进 `queued_messages` 并返回 202 与这个 run；否则在队列里剩下的消息之后写下这条消息并建 run，返回 201。排队的消息不是对话消息，也不是记忆来源。interjection middleware 在 run 每次调用模型前把队列里的文字消息按发送顺序写进对话、绑定到这个 run（取 run 的 turn）并追加到 agent state 与 run 的历史，每条记一个 `run.input` 事件；带文件的消息与它之后的留到下一个 run。run 结束时，若对话里没有别的 run 在运行或等待审批，同一事务把剩下的消息写在回复之后、建下一个 run 并把它写进终止事件的 `next_run_id`，随后执行它。终止前没能接手的路径（setup 失败、Acorn 停止）留下的消息由 `serve` 的续跑扫描在启动时与每分钟起 run，owner 的下一条消息也会先带上它们。队列随对话删除。

## 持久化与 store 边界

- **SQLite adapter 不跨层泄漏**：production 代码只允许 `internal/wire` 直接 import `internal/store`；其他包只依赖 core 定义的接口或 `internal/store` 导出的记录与错误。
  - `tests/architecture/dependency_direction_test.go`
- **数据库结构有版本**：`PRAGMA user_version` 记录结构版本。空库在一个事务里按当前结构建好并写入版本；旧版本库在独占存储锁下按顺序迁移，每一步与版本号在同一事务提交，外键在迁移期间关闭、每一步结束时不得有失效外键；没有版本号或版本更新的库拒绝打开。每个版本的结构记录在 `internal/store/testdata/schema/vN.sql`，从任一记录版本升级的结果必须与新建库的结构完全一致。
  - `internal/store/schema_version_test.go`
- **备份不打断运行，恢复要求停机**：`acorn backup` 写入 `backup.dir`（为空表示关闭备份）、保留最新 `backup.keep` 份快照，经只读连接 `VACUUM INTO` 生成数据库快照，校验完整性与结构版本后以原子重命名发布；产出文件与对话文件在快照之后镜像，只增不删，快照引用的文件都在镜像里。`acorn restore` 持有独占存储锁，Acorn 运行时拒绝执行，先校验快照再替换数据库并清除 WAL。
  - `internal/wire/backup_test.go`
- **写入单连接，记忆读取并行**：所有写入与事务经一个 SQLite 连接串行执行；记忆召回与整合候选的读取走 `query_only` 的 WAL 只读连接池，写事务进行中也能读到已提交的数据，只读池拒绝写入。
  - `internal/store/store_read_pool_test.go`
- **时间由调用方给出**：记忆与约定的 created_at/recorded_at/updated_at 与 `notifications` 的 created_at 由写入方的时钟决定，store 拒绝缺少时间的写入；时钟只在组合根注入，工具、presence、wake 调度器与推送 sender 共用一个。
  - `internal/store/store_presence_test.go`
  - `internal/wire/wake_acceptance_e2e_test.go`

## 上下文与记忆

- **上下文管理由 Eino middleware 承担**：summarization 在 token 超过 `上下文窗口 - 输出预留 - presence 上限 - 压缩余量` 时总结历史；reduction 只做 clear（保留最近 8 轮工具调用原样）。上下文窗口取模型表里的值，模型表以外的模型取 provider 的 `context_window_tokens`，没写时拒绝启动，模型表里的模型写了也拒绝；presence 上限 4000 与压缩余量 32000 是代码常量。
  - `internal/runtime/agent_test.go`
  - `internal/config/config_models_test.go`
- **两种压缩写同一份固定格式**：线程摘要与 run 内压缩依次写 `## Goal`、`## Constraints and preferences`、`## Progress`（其下 `### Done`、`### In progress`、`### Blocked`）、`## Key decisions`、`## Next steps`、`## Critical context` 九个段落，再由 Acorn 接上 `## Files read` 与 `## Files changed`。模型的回复以 `## Goal` 开头，九个标题各自独占一行、只出现一次且顺序不变，不写两个文件段落，没有内容的段落写 `(none)`，否则报 `ErrSummaryFormat`。两者的指令都要求把输入当作不可信来源数据、assistant 的建议仍记为建议、略去密码、access token、API key 与验证码、原样抄写 job、跟进与目标的 id 和工作机与笔记路径，并在已有摘要上更新。文件段落只认 `files` 的 read/write 与 `send_file` 调用参数里的路径：按最后一次接触从旧到新排列，写过的文件只列在 Files changed，参数解析不了的调用与带凭据的路径不计，没有文件时写 `(none)`。线程摘要的输入把上一份摘要放在 `<previous_summary>` 里，具体事实带来源 id；它的文件段落取自被摘要的对话轮次里已结束（succeeded 或 failed）的 run，只计结果是 JSON 对象的成功调用（被拒绝或被规则拦下的不计），这些调用的结果来源加入摘要的来源，遗忘其中任一个时摘要失效并重建，有排除的调用不再计入；文件段落至多占摘要预算的四分之一，超出时从最久没接触的文件起略去并注明略去的数目，模型的输出上限是摘要预算减去文件段落再减 64，写在指令里；回复缺段落时重新生成一次，仍缺即报错且不保存；摘要预算不足 512 token 时不写摘要。run 内压缩替换 Eino 的默认指令，模型至多写 4096 token，回复不合格式时这次调用失败，与 provider 错误一起按 summarization 的重试规则最多重试 3 次；文件段落取自被压缩消息里的调用（结果可能已被 reduction 清除，故不看结果），文件列表记在摘要消息上，随 checkpoint 保存，同一 run 的下一次压缩接着它合并。

  - `internal/runtime/compaction_test.go`
- **人格只由 owner 修改**：人格存在 SQLite 的 `persona_revisions`，最新 revision 是当前人格；每次保存是基于读到的 revision 的新 revision，并发修改显式失败；内容去掉首尾空白后不能为空，至多 8 KiB。启动时没有人格才以 release 身份写入默认人格，已有人格不被覆盖。owner 经 `/v1/persona` 与 `acorn persona` 保存，agent 没有写人格的工具。每个 run 开始时读当前人格。

## 工作机

- **工作机只经带 token 的 HTTP 调用**：serve 不接触容器引擎；`acorn workstation serve` 在容器里运行，每个请求校验 bearer token，token 少于 32 字符时拒绝启动。`shell`、`job`、`follow_up`、`files` 与 `send_file` 是 deferred 工具，未配置 `workstation.url` 时以原因禁用。
  - `internal/workstation/workstation_test.go`
- **按段编辑只改旧文本所在之处**：`files` 的 edit 与 `knowledge_edit` 都经 `internal/textedit` 修改文本：每段旧文本对照修改前的全文，必须只出现一次；完全对不上时把行尾空白、弯引号、破折号与不换行空格归一后再找，仍然对不上或出现多次就报错并指出是第几段；各段不能重叠；要么全部生效，要么文本不变。CRLF 换行与 BOM 保持原样，结果给出每段新文本所在的行。工作机写到旁边的临时文件再整体换入，保留文件权限，只改 UTF-8 文本文件。
  - `internal/textedit/textedit_test.go`
  - `internal/workstation/workstation_test.go`
  - `internal/knowledge/knowledge_test.go`
  - `internal/tools/workstation_tools_test.go`
- **shell 的命令是任务，长命令留在后台**：工作机为每条命令建 `~/.jobs/<id>/`，记下命令、状态与起止时间，stdout 与 stderr 交错写进 `output.log`，超过 64 MiB 的部分计数后丢弃；命令在自己的进程组里运行，至多 24 小时，到时或经 `job stop` 先 SIGTERM、5 秒后 SIGKILL 整组。`shell` 等到 `wait_seconds`（0 到 600，默认 120）为止：结束了就返回退出码与输出的首尾，还在跑就返回任务 id 与输出的末尾，任务继续。输出摘录与分页读取都不切断 UTF-8 字符，摘录写明省略了多少字节、从哪读回。工作机重启时仍记为 running 的任务标为 lost，结束超过 7 天的任务目录被删除。
  - `internal/workstation/jobs_test.go`
  - `internal/tools/workstation_tools_test.go`
- **工作机里的进程用不了工作机 API**：监听非 loopback 地址时，serve 拒绝来自自己地址（loopback 与本机网卡地址）的请求；启动时把 token 从进程环境里移除，它运行的命令、技能包 MCP 服务器与触发器都继承不到。
- **后端的 stdio MCP 服务器只继承少数环境变量**：Acorn 进程的环境里只有 `PATH`、`HOME`、`USER`、语言与时区、临时目录、证书与代理变量到服务器，API key 与工作机 token 在内的其余变量只有写进 provider 的 `env` 才到；`env` 的值展开环境变量。
  - `internal/workstation/token_test.go`
  - `internal/tools/workstation_tools_test.go`
  - `internal/config/config_workstation_test.go`
- **文件经工作机往返**：每次 run 前，对话里已发送的 owner 文件按 id 复制到工作机 `~/uploads/<file_id>/<文件名>`（写在旁边再整体换入），不再属于任何对话的副本被删除；复制失败时 run 继续，模型从消息附注里得知原因。模型看到每条 owner 消息附带的文件名、类型、大小与工作机路径，≤10 MiB 的 JPEG/PNG/WebP/GIF 作为图片输入随消息交给模型并按 `core.ImageInputTokens` 计入输入预算。`send_file` 是 eager 工具，经工作机 `/v1/files/raw` 读取文件，超过 `files.max_send_mib` 时失败，存为本 run 的 agent 文件。对话的消息把 agent 文件列在本 run 的回复下；run 没有回复时，列在它的输入之后一条以 run id 为 id 的无文本 assistant 消息里。

- **伴随进程常驻**：`acorn workstation serve --keep` 的每个伴随进程在独立进程组里运行，退出后按退避重启，serve 停止时连同其子进程一起结束；日志按名字加前缀并去掉终端颜色码。

- **包的 MCP 服务器由工作机守护**：`PUT /v1/mcp` 给出应运行的包（名字、包哈希、密钥环境变量），工作机停止其余服务器，包哈希或环境变了的重启，新的启动，最多等 90 秒报告每个服务器能否服务。服务器与伴随进程用同一个 supervisor：以包目录为工作目录、独立进程组、退避重启，stderr 以 `mcp:<name>` 为前缀写入日志；包目录的哈希必须与请求一致。工作机以 MCP 客户端经 stdio 连接服务器，把它的工具挂在 `/v1/mcp/<name>` 的 streamable HTTP 上，经 bearer token 鉴权，会话跨重启保留；服务器 stdout 里不是 JSON-RPC 消息的行以 `stray stdout:` 记进 `mcp:<name>` 日志并跳过，会话照常；进程退出或 stdio 会话仍然断开（管道关闭、客户端解不开的消息、超长的行）都算一次失败，停掉进程后退避重启，重启进行中的请求等它结束再报告；不再运行的服务器的地址返回 404。serve 停止时这些服务器一起结束。
